# OjiMate 要件定義（現行設計）

更新日: 2026-09-29

対象: 現在のリポジトリにあるWebアプリと任意のAI Worker
この文書は現行コードで実現している動作を記述する。将来案や外部サービスの設定完了を前提にしない。

## 1. 目的と基本方針

OjiMateは、おじさんを自分の分身として眺めながら集中するブラウザ用タイマー。集中した時間を仮想の収入として積み上げ、ふたりの住まいが変わっていく。途中でやめても、その時点までの実績を記録し、ユーザーを責めない口調で再開を促す。

画面、説明文、セリフの表記は「おじさん」に統一する。アプリ名は「OjiMate」とする。

## 2. 対象と前提

| 項目 | 現行要件 |
| --- | --- |
| 利用端末 | スマートフォン、タブレット、PCのブラウザ |
| 配信 | HTTPSの静的サイト。HTML、CSS、JavaScript、アイコンを配信する |
| アカウント | 不要。ユーザー登録とクラウド同期はない |
| 保存先 | 基本データは利用中のブラウザの `localStorage`。端末やブラウザ間で共有しない |
| 通信 | 通常のセリフとタイマーに外部APIは不要。初回のアセット取得、Webフォント、任意のAI会話には通信が必要 |
| 3D | Three.jsで描画。WebGLが使えない場合は2D表示で操作を継続できる |

## 3. 画面と主要フロー

| ID | 画面 | 要件 |
| --- | --- | --- |
| UI-01 | タイトル | ロゴ、短い説明、開始ボタンを表示する。開始後にアプリ本体を起動する |
| UI-02 | 初回案内 | おじさんが分身であることを伝え、ホーム、時間設定、開始、残り時間の操作を順に案内する。スキップ可能。表示済み状態を保存し、ホームの「使い方」から再表示できる |
| UI-03 | ホーム | 現在の住まい、仮想収入、利用日数、累計集中時間、次の家までの進捗、直近の記録、おじさんのセリフを表示する。スマホでは家または「記録」から記録を開き、十分な高さのPC画面では記録を常設する |
| UI-04 | 時間設定 | 5～120分を5分刻みで選び、勉強・制作・読書・その他からタグを選ぶ。前回選択した時間を初期値とし、おすすめ時間は別に示す。ホームへ戻れる |
| UI-05 | 集中 | 残り時間と進捗ゲージを表示する。ゲージを開くと一時停止、休憩、終了の操作を選べる。音のON/OFFは操作バーから変更できる |
| UI-06 | 終了後 | 完了または中断の結果を記録し、ホームに戻す。完了時のみ「しんどかった」「いけた」の感想を聞き、次回の提案に反映する |

基本遷移は `タイトル → ホーム → 時間設定 → 集中 → ホーム`。時間設定からホームへ戻れる。集中セッションが保存されている場合は、タイトル後に集中画面へ復元する。

## 4. 機能要件

### タイマーと記録

| ID | 要件 |
| --- | --- |
| FN-01 | 通常モードの1分は実際の60秒。時刻差から経過時間を計算し、描画の停止・再開に時間計測を依存させない |
| FN-02 | 集中、一時停止、休憩、再開の状態を持つ。一時停止と休憩中は経過時間を増やさない |
| FN-03 | 実行中の時間、設定時間、タグ、更新日時を保存する。再読み込み時は離れていた経過時間を反映し、一時停止状態で復元する。離れている間に満了していた場合は完了処理へ進める |
| FN-04 | 満了は設定した分数を記録する。途中終了は経過した整数分を記録し、1分未満は0分として扱う。終了操作の重複で報酬や履歴を二重加算しない |
| FN-05 | 誤操作防止のため、終了は約1.4秒の長押し、または4秒以内の2回押しで確定する。キーボードでも2回押しを利用できる |
| FN-06 | 直近の完了・中断、分数、タグ、日付を保存する。保存する履歴は最大12件で、ホームに表示するのは直近7件 |

### 成長とおじさんの反応

| ID | 要件 |
| --- | --- |
| FN-07 | 記録した集中時間1分につき仮想収入を240円加算する。累計集中時間と仮想収入は中断後も減らさない |
| FN-08 | 住まいは収入の到達額に応じて5段階で変化する。到達額は24,000円、60,000円、110,000円、180,000円。最終段階は庭付きの家 |
| FN-09 | 利用日数と完了回数からおじさんの関係段階とセリフを変える。中断が続いても既に得た関係段階を下げず、当日の提案を短めにする |
| FN-10 | おすすめ時間は初期15分。完了回数に応じて30分、50分へ変え、直近2回以上の中断または当日の「しんどかった」回答があれば15分を示す。おすすめ操作を押すまでユーザーの選択を上書きしない |
| FN-11 | 時刻、天候、訪問間隔などに応じておじさんのセリフや3Dの様子を変える。不在による雑草などの見た目の変化は実績を減らさない |

### 表示、音、アクセシビリティ

| ID | 要件 |
| --- | --- |
| FN-12 | 3Dの風景をドラッグで見回せる。WebGLを使えない環境では軽量な2D表示を出し、タイマーと画面遷移を使えるようにする |
| FN-13 | 音は初期OFF。明示的にONにした場合だけ集中時の環境音を再生し、設定を保存する。音声機能に失敗してもタイマーは継続する |
| FN-14 | スマホは縦の一画面、幅768px以上の十分な高さの画面は3D風景と操作パネルを横並びにする。横向き・低い画面では各操作が画面外に隠れないよう再配置またはスクロールさせる |
| FN-15 | ボタンと入力に名前・状態・フォーカス表示を設ける。チュートリアル中のフォーカス移動、Escapeによる閉鎖、`prefers-reduced-motion`、状態の読み上げに対応する |

### 保存、オフライン、任意のAI会話

| ID | 要件 |
| --- | --- |
| FN-16 | 記録、住まい、訪問、チュートリアル、音設定などをブラウザ内に保存する。読み込み時は保存値の型と範囲を検証し、保存不能時も初期状態で利用できる |
| FN-17 | HTTPSではService Workerを登録し、アプリ本体、アイコン、同梱Three.jsをキャッシュする。初回オンライン読み込みとキャッシュの準備後にオフライン再訪できる。AI会話はオフラインでは利用しない |
| FN-18 | AI会話は利用者がWorkerの接続先と合言葉を設定した場合だけ有効。未設定時や接続失敗時は端末内のセリフを表示する。接続先は `localStorage`、合言葉はタブの `sessionStorage` に保存する |
| FN-19 | 任意のAI Workerは許可された配信元からのPOST JSONのみを受け、合言葉を検証し、入力サイズと上流応答時間を制限する。プロバイダーの秘密鍵をブラウザへ渡さない。Workerの配備と秘密値の設定は別途必要 |
| FN-20 | `?demo=1` の短縮タイマーと `?force2d=1` の軽量表示確認は `localhost` / `127.0.0.1` だけで有効。デモ記録は通常記録とは別の保存領域に置く |

## 5. データと対象外の範囲

- ローカル保存の主な項目は利用日、完了・中断回数、累計集中分数、直近の履歴、仮想収入、住まい段階、前回選択時間、進行中セッション、感想、案内の表示済み状態、音設定、AI接続先。
- 作業内容そのものを入力する欄はない。タグは4種類の固定値。
- AI会話を有効にした場合に送る文脈は、前回の選択時間、直近の結果、連続完了・中断回数、関係段階、深夜かどうか。全履歴とプロバイダーの秘密鍵は送らない。
- ブラウザのデータ削除、別ブラウザ・別端末への移動では記録を引き継げない。エクスポートとクラウド同期は現行範囲外。
- 仮想収入はゲーム内の数値で、現実の金銭や支払いには使えない。

## 6. 現行実装の受け入れ基準

1. 初回利用でタイトルから案内、時間設定、集中開始まで進め、2回目以降は案内を自動表示しない。
2. 5～120分の設定、タグ選択、一時停止・再開・休憩・終了、満了が操作でき、結果が1回だけ記録される。
3. セッション中の再読み込み後も経過時間が失われず、一時停止状態から再開できる。
4. 320px程度のスマホからPCまで、主要ボタンを操作でき、横方向に内容がはみ出さない。
5. WebGLと音声が利用できない場合も、タイマー操作が継続できる。
6. `npm run check` が成功し、公開版はHTTPSでアプリ本体と必要なアセットを配信できる。

## 7. 実装の構成

アプリ本体は静的な `index.html` に画面、状態、3D表現をまとめ、`tokens.css` にデザイン値を置く。`sw.js` と `manifest.webmanifest` がPWAを構成し、`vendor/three.r128.min.js` を同梱する。`worker/` は任意のAI会話プロキシであり、配備しなくても本体の機能を利用できる。`tests/smoke.mjs` は主要な構成と回帰条件を確認する。
